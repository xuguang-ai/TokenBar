Codex app-server JSON-RPC sequence for reading plan usage (verified live with codex-cli 0.160.0, 2026-10-06)
=====================================================================================================

Transport : child process stdio. One JSON object per line, UTF-8, terminated by "\n" (no Content-Length framing).
Envelope  : JSON-RPC 2.0 shape WITHOUT the "jsonrpc" member (server omits it; tolerates it if a client sends it).
            Request {"method","id","params"?}; Response {"id","result"} | {"id","error":{"code","message","data"?}};
            Notification {"method","params"?} (no id). Ids may be integers or strings.
Spawn     : [env CODEX_HOME=<profile dir>] RUST_LOG=error \
            <codex> -c memories.generate_memories=false -c memories.use_memories=false app-server --listen stdio://
            (--listen stdio:// is the default; the -c overrides are per-process and optional; do NOT pass
             --analytics-default-enabled, that flag is for first-party IDE clients)

->  = TokenBar to app-server (stdin)      <-  = app-server to TokenBar (stdout)

1  -> {"method":"initialize","id":0,"params":{"clientInfo":{"name":"tokenbar","title":"TokenBar","version":"0.0.1"},"capabilities":{"experimentalApi":false,"requestAttestation":false}}}
      (only clientInfo.name + clientInfo.version are required; capabilities may be omitted/null.
       clientInfo.name must be a valid HTTP header value: it becomes the `originator` header and the User-Agent prefix)
2  <- {"id":0,"result":{"userAgent":"tokenbar/0.160.0 (Mac OS 26.7.0; arm64) unknown (tokenbar; 0.0.1)","codexHome":"/Users/xai/.codex","platformFamily":"unix","platformOs":"macos"}}
      (~33-89 ms after spawn; codexHome tells you which profile/account the server is using)
   <- {"method":"remoteControl/status/changed","params":{...}}            notification, ignore
3  -> {"method":"initialized"}
4  -> {"method":"account/read","id":1,"params":{"refreshToken":false}}   (params REQUIRED; {} also valid)
5  -> {"method":"account/rateLimits/read","id":2,"params":{"excludeResetCreditDetails":true}}   (params optional)
      (4 and 5 can be pipelined; responses arrive by id, in any order, interleaved with notifications)
6  <- {"id":1,"result":{"account":{"type":"chatgpt","email":"<email>","planType":"plus"},"requiresOpenaiAuth":true,"workspaceRouting":{"chatgptAccountId":"<masked>","backendOrigin":"https://chatgpt.com","accountRoutingOverride":"NO_CONSTRAINT"}}}
      (workspaceRouting is an experimental field, sent even with experimentalApi=false; ignore unknown fields)
7  <- {"id":2,"result":{"ordinaryUsageAllowed":true,"rateLimits":{"limitId":"codex","limitName":null,"normalModelSlug":null,"primary":{"usedPercent":0,"windowDurationMins":300,"resetsAt":1791269178},"secondary":{"usedPercent":16,"windowDurationMins":10080,"resetsAt":1791835147},"credits":{"hasCredits":false,"unlimited":false,"balance":"0"},"individualLimit":null,"spendControlReached":false,"planType":"plus","rateLimitReachedType":null},"rateLimitsByLimitId":{"codex":{...same as rateLimits...}},"rateLimitResetCredits":{"availableCount":0,"credits":null},"accountId":"<masked>","rateLimitUpsell":null}}
      (~0.3-0.7 s; the server calls GET https://chatgpt.com/backend-api/wham/usage with Codex's own token)
   <- {"method":"account/updated","params":{"authMode":"chatgpt","planType":"plus"}}   notification, ignore
8  close stdin (EOF)  ->  server exits with code 0 in ~10 ms. Escalate to SIGTERM after 3 s, then SIGKILL.

Observed error responses
------------------------
request before initialize        -> {"error":{"code":-32600,"message":"Not initialized"},"id":1}
second initialize                -> {"error":{"code":-32600,"message":"Already initialized"},"id":4}
account/read without "params"    -> {"error":{"code":-32600,"message":"Invalid request: missing field `params`"},"id":6}
unknown method                   -> {"error":{"code":-32600,"message":"Invalid request: unknown variant `nope/nope`, expected one of `initialize`, ..."},"id":7}
not logged in (empty CODEX_HOME) -> account/read  => {"account":null,"requiresOpenaiAuth":true,"workspaceRouting":null}
                                    rateLimits    => {"error":{"code":-32600,"message":"codex account authentication required to read rate limits"},"id":5}
(requests sent after the initialize response but before "initialized" were accepted; send "initialized" anyway)

Server-to-client requests (have both "method" and "id"): none occurred in managed ChatGPT auth mode. Possible ones
include account/chatgptAuthTokens/refresh (external-token mode only) and approval prompts (only during turns).
Reply with an error such as {"id":X,"error":{"code":-32601,"message":"not supported"}} so the server never blocks.

Field semantics (v2, camelCase)
-------------------------------
usedPercent        integer 0-100 (required).            remaining = 100 - usedPercent
windowDurationMins 300 = 5-hour window, 10080 = weekly. Label windows by THIS value, not by primary/secondary position.
resetsAt           unix epoch SECONDS (nullable). When usedPercent == 0 the window has not started, and resetsAt
                   is about now + window, advancing on every poll, so don't show a ticking countdown.
rateLimitsByLimitId multi-bucket view keyed by metered limit id ("codex"); rateLimits mirrors the main bucket.
rateLimitReachedType non-null when blocked: rate_limit_reached | workspace_owner_credits_depleted |
                   workspace_member_credits_depleted | workspace_owner_usage_limit_reached | workspace_member_usage_limit_reached
ordinaryUsageAllowed false = blocked, null = unknown (don't infer recovery from percentages).
credits            {hasCredits, unlimited, balance(string)}: purchased credits beyond the plan.
planType           free|go|plus|pro|prolite|promax|team|business|enterprise|edu|... |unknown

Methods TokenBar must NEVER call: account/rateLimitResetCredit/consume (spends a reset credit),
account/sendAddCreditsNudgeEmail, account/logout, account/login/start, and account/read with refreshToken:true.
